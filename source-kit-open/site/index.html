Source Kit is an iOS camera that cryptographically seals every photo and video at the moment of capture, on-device, with genuine C2PA Content Credentials embedded in the file. This is the auditable core — the part a skeptic needs to check the claims, plus the lab that reproduces every one of them offline.

A valid signature proves the bytes are unchanged since signing, and which key signed them. It does not prove what a camera pointed at — and the app says so, in plain language, on every verification.

Two axes, never one score

Most "authenticity" tools collapse everything into a single green checkmark. Source Kit refuses to. Integrity — have the bytes changed since signing? — and credibility — whose key is this, and what does it vouch for? — are different questions with different failure modes, so they are computed and shown separately.

A failed attestation, timestamp, or chain is a loud warning that never silently moves the integrity verdict. What was not checked is stated on every report, in the app, every time.

The label, not the adjudication

The project borrows museum grammar deliberately: a sealed file is an exhibit, its manifest is the label on the wall beside it. A label describes an object without pronouncing it genuine — which is exactly the boundary a provenance tool must hold.

So the verifier is evidence for a journalist to weigh, not an automated verdict. That single design decision runs through every file in this repository.

01

What happens when you press the shutter

Every step runs on the device. Sealing and checking both work fully offline; the few optional network calls are enumerated, named, and never hidden.

1

Hash the exact media bytes

SHA-256, chunked so verification never has to load a whole video into memory. src/lib/fileHash.ts

2

Record capture context

GPS (opt-in), compass heading, barometric altitude, an accelerometer motion signal — each a lead a desk corroborates, never proof. src/sensors/

3

Sign the attestation record

ECDSA P-256 (ES256), key held non-extractably in the Secure Enclave, optionally App Attest–certified. src/lib/deviceKey.ts · src/lib/sign.ts

4

Embed Content Credentials

A spec-conformant C2PA manifest — CBOR claim, hard binding, COSE_Sign1 — written into the JPEG/PNG/MP4/MOV/M4A itself. archive/handrolled-verifier/c2pa.ts

5

Add a second signature

An ML-DSA-65 (FIPS 204) post-quantum signature over the same commitment, so a future break of P-256 doesn't silently invalidate the archive. src/lib/pq.ts

6

Anchor in time

An RFC 3161 timestamp countersignature when online; an OpenTimestamps/Bitcoin receipt for independent proof-of-existence. Offline captures sign without and say so. src/lib/timestamp.ts · src/lib/ots.ts

The commitment binds the layers together on purpose: the post-quantum public key is committed inside the classically-signed payload, so a stripped PQ layer is detectable and a forged one binds to nothing. 02

A verifier that fails closed

The X.509 stack is pure TypeScript — no WebCrypto, no network, no runtime-fetched roots. It does the things hand-rolled verifiers usually skip, because those are where forgeries hide.

What it enforces

  • Every link's signature verifies under the next certificate's key; issuer and subject names chain byte-for-byte.
  • Certificate validity is evaluated at the verified signing time, never the verifier's clock.
  • RSA exponent ≥ 3 and odd, modulus ≥ 2048 bits; strict full-block PKCS#1 v1.5 comparison (closes signature-forgery shortcuts).
  • CA discipline in both directions: a non-leaf must be a CA; a leaf must not be able to sign certificates; pathLenConstraint is honored.
  • An ambiguous certificate set is refused, not guessed at.

Signer identity resolves only against out-of-band anchors — this device, or an organization credential — never a self-asserted name inside the file. A self-issued certificate claiming O=Reuters does not anchor, and the suite proves it: the exact attack an external audit threw at an early build is now a permanent regression test.

03

Binding a signature to real hardware

Apple gives apps no direct access to App Attest keys. Source Kit uses emulated key attestation to prove the signing key lives on a genuine device running a genuine build — verifiable by anyone, offline.

The trick is a commitment: the App Attest clientDataHash is set to SHA256(challenge ‖ signingPublicKey). Apple's nonce extension in the attestation leaf certificate then vouches for exactly that key — not just some key. The binding rides inside every C2PA manifest, so it can be re-checked long after capture, with no server involved.

Attestation is strictly on demand. The app ships with no registry address bundled and makes no launch-time network call of any kind. Offline devices simply sign unattested and say so. A software-keychain fallback exists and is labeled as such in the UI — the app never dresses it up as hardware.

04

The honesty is enforced in code

Anyone can claim strong cryptography. What's unusual here is that the project's restraint — the refusal to overclaim — is compiled and tested, not just promised in a README.

Words the product may never say in a verdict

A test suite scans every banner, chip, and badge. If any of these words appears in verdict position, the build fails:

Checks we examined and refused to build

A refusal belongs on the record — a silently absent check looks like an oversight a future contributor will re-propose. Three of the seven, in brief:

Rejected

Error level analysis

Its own author discredits it as forensics: the pattern tracks save history, not edit history, and one re-save flattens it. A heat map that glows on command is theatre.

Rejected

AI-detector classifiers

"87% AI-generated" is an unverifiable probability in verdict clothing. The reader cannot re-derive it, and it fails silently on generators the model never saw.

Rejected

Fused trust scores

Collapsing independent signals into one number destroys the information a reader needs — which signal failed, and whether it bears on integrity or credibility at all.

05

Don't take our word for it — run it

Every cryptographic claim on this page can be checked offline in about five minutes. The suites sign fresh media with a random lab key on each run; nothing is canned.

# node 20+, ffmpeg, and (for the independent checks) c2patool
node tests/stage.mjs
cd tests/.staged && npm install

The staging script rewrites only device-service imports — keychain, filesystem, device model — to tiny shims. Every cryptographic operation (canonicalization, CBOR, COSE, hashes, X.509, ECDSA, RSA, CMS) runs as the real shipping code.

The independent checks validate our output against c2patool — the reference C2PA implementation — not just against ourselves. In CI it runs against a SHA-256-pinned binary, verified before extraction.

What's open, and what deliberately isn't

Everything that makes a security claim is here. What's withheld makes no claims — and there's a reason for the line.

Why the app shell stays out

A provenance app's entire value is that users can trust what they install. A one-command fork shipping a pixel-identical lookalike under the same name is the one supply-chain attack worth cheaply preventing. Key custody, attestation, signing, and verification are all here; the shell is not, and it makes no security claim.

Forking this core to build your own signer is the point. Ship it under your own name.

License & credit

Apache-2.0, with a NOTICE that must travel with every redistribution (§4(d)) and a TRADEMARK.md: the code is free to fork, the name Source Kit is not. That combination keeps the tooling open while keeping a lookalike from trading on verification claims it doesn't implement.
